## Codebase-memory-mcp: adopted design, not installed software

**Decision:** prefer the whole, pinned upstream MCP binary as a separately supervised **optional code-intelligence service** in a disposable test environment rather than copying/forking thousands of source files into FIRBO. Import specific metadata/methods only if a gap is actually demonstrated. Do not use `curl | bash`, uncontrolled `install`, `update`, auto-configure all detected agents, or a shared account-wide daemon on production.

1. **Provenance and review.** Compare pinned source, latest published release, MIT notice, dependency/SBOM, checksums and SLSA attestations. Independent sandbox scan / release smoke test. Main branch pin and release version are distinct: latest release observed `v0.11.0` (2026-09-15), branch pin above is newer; never assume identical bytes/features.
2. **Isolated proof.** Start binary in an unprivileged temporary account/container with **read-only single repository clone**, no customer files/credentials and no outbound network beyond vetted update-check policy. `CBM_ALLOWED_ROOT` limited to that clone, owner-only `CBM_CACHE_DIR`, disabled global installation/hooks/watchers/UI or firewall-bound loopback-only UI. Explicit indexing only.
3. **Useful tasks and performance.** Evaluate `get_architecture`, `search_graph`, call/HTTP edges, `detect_changes`, source attribution, fresh Git commit reindex and relevance against scoped manual code navigation. Capture indexing latency, CPU/RAM, token use, cost and false-positive symbols. Stop/restart and rebuild persistence acceptance.
4. **Multi-tenant boundary.** Never share a code graph/cache or MCP socket across customer organizations or across private repositories without explicit authorization. Authenticated company/project allowlists, separate cache/index processes for each tenant, ownership checks for API calls and no indexing secrets/`.env`. An internally hosted coding assistant may see FIRBO repos; Business+ users may see only explicitly authorized *their own* code, not owner's internal FIRBO source.
5. **Promotion after core gates.** First close CEO→VPS→Debian real task + truthful terminal receipt + Stop, native memory 503 repair and scoped agent management. Then wire codebase MCP as a read-only role-restricted **Developer/QA tool**, add tracing/cost envelope, quality comparisons and recheck release permissions. Do not enable it automatically for every employee or owner Mac Catalina.

Important upstream behavior: native `install` may modify per-user coding agent configs and restart processes; daemon and watcher coordination can affect other chats and workloads. CBM indexing of source **is not** CEO chat memory, Mem0, an executor, browser or host-wide shell access. Local code graph is not private automatically once exposed via SaaS; FIRBO's auth and isolation must surround the MCP connection.
